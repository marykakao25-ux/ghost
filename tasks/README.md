# Задачи (`tasks/`)

Эта папка — **единственный источник правды** о том, кто над чем работает. Она живёт в ветке `main`
и меняется вместе с кодом по одним и тем же правилам.

## Устройство

```
tasks/
├── README.md            этот файл
├── TEMPLATE.md          шаблон новой задачи
├── T-XXXX-short-name.md задача (front matter + описание)
├── claims/              активные блокировки: claims/T-XXXX.md (создаёт claim.ps1)
└── done/                завершённые задачи (переносит release.ps1)
```

## Статусы

| Статус | Значение |
|---|---|
| `todo` | задача свободна, можно брать |
| `claimed` | лок взят, работа ещё не начата |
| `in-progress` | идёт работа в `task/T-XXXX-*` |
| `review` | PR открыт, ждёт проверки |
| `done` | смержено в `main`, файл лежит в `tasks/done/` |
| `blocked` | есть внешняя блокировка, причина — в «Заметках» |

## Правило блокировки: A + B

Одну задачу может взять только один агент. Защита двухслойная:

* **Слой B (жёсткий, первичный).** Ветка `claim/T-XXXX` — уникальная ссылка в git. Захват делает
  `git push origin HEAD:refs/heads/claim/T-XXXX`; если ссылка уже существует, push отвергается
  сервером. Обойти это нельзя — ни правилами, ни правами. Если push уходит из форка, GitHub
  переименует ветку в `<owner>/claim/T-XXXX`; скрипты распознают это и считают задачу занятой.
* **Слой A (реестр).** Файл `tasks/claims/T-XXXX.md` в `main` — человекочитаемый список владельцев,
  TTL и захваченных путей. Он же даёт защиту от двух задач на одном файле (`paths`).

**Никогда не берите задачу вручную.** Всегда через скрипт — он делает оба шага и сам откатывается
при неудаче:

```powershell
pwsh -File scripts/agent/claim.ps1   -Task T-0012 -Owner cline
pwsh -File scripts/agent/status.ps1
pwsh -File scripts/agent/release.ps1 -Task T-0012
```

## Соглашение о `paths`

`paths` в front matter — это **контракт**. Задача не имеет права менять файлы вне этого списка:

* `claim.ps1` откажется брать задачу, чьи `paths` пересекаются с путями любой активной задачи;
* CI (`agent-guard.yml`) уронит PR, если дифф выходит за `paths` задачи.

Следствия, которые надо соблюдать при заведении задач:

1. **Одна сцена (`.tscn`) — одна задача.** Два агента в одном `.tscn` дают неразрешимый конфликт.
2. Общие файлы (`project.godot`, `README.md`, `AGENTS.md`) меняет только `infra`-задача.
3. Новые ассеты кладутся в **новый** подкаталог (`assets/sprites/dog/`), а не в существующий,
   иначе два агента одновременно правят один каталог.

Пересечение считается по префиксам: путь задачи `assets/sprites/cat` конфликтует с
`assets/sprites/cat/cat_idle1.png`.

## Ручные операции

* **Takeover** просроченного лока: `claim.ps1 -Task T-XXXX -Takeover` — только если владелец пропал.
  Запись о снятии лока остаётся в истории задачи.
* **Аварийное снятие** зависшего лока: `pwsh -File scripts/agent/force-release.ps1 -Task T-XXXX`
  (нужно проверить, что работа не потеряется: `git log origin/task/T-XXXX-*`).
